# WoWSims Forever SIML

SIML is the text format of the rotations (APLs), gear sets and whole sim setups. Each file reads as a proto
(`proto/apl.proto`, `proto/api.proto`) and prints back from it, 1:1. The hunter's presets are SIML; the other specs
keep JSON presets until each moves, and the Go suites and the site read either. `sim/siml/SPEC.md` is the full
language and wins on any doubt.

`wowsimcli siml llm` writes this skill: the part above "Actions" from `sim/siml/llm_head.txt`, the rest from the
protos, so a change to `proto/apl.proto` shows up here once `make siml` runs. Edit the head, never this file.

## Where things live

- `sim/siml/SPEC.md`: the language; §6 rotations, §7 names, §8 what the protos derive, §13 diagnostics.
- `sim/siml/names.json`: every name a file may write, per class and namespace. Generated by `make siml-names`.
- `sim/siml/forms.json`: sections, units and short forms; everything else comes from the protos.
- `sim/siml/testdata/`: the corpus. `parse/` (text and the JSON it reads as), `print/` (JSON and the text it prints
  as), `errors/` (with `.diag`), `format/`, `splice/`, `tables/` (name tables refused and accepted).
- `ui/specs/hunter/dps/`: the presets. `defaults.siml`, `apls/*.apl.siml`, `gear_sets/*.gear.siml`,
  `builds/*.siml`.
- `cmd/wowsimcli/cmd/siml*.go` the CLI, `sim/siml/lsp` the language server, `tools/vscode-apl` the VS Code
  extension, `tools/zed-siml` the Zed one, `tools/tree-sitter-siml` the tree-sitter grammar Zed colours with. A change
  to the syntax (`lex.go`, `syntax.go`) changes the grammar too: `npm run check` in `tools/tree-sitter-siml`.

## CLI

`make bin/wowsimcli` builds it with the database (`--tags=with_db`), which the siml commands need for the name table.

- `siml parse [-json] <file>`: does it load; `-json` prints the proto it reads as.
- `siml fmt -check|-w <paths>`: the canonical form; under `ui/specs` also warnings, raw refs and stale names.
- `siml print -kind apl|gear|siml [-spec hunter] x.json`: JSON as SIML.
- `siml verify x.json x.siml`: does `x.siml` read back as `x.json`.
- `siml sim < request.json`: sims an `.apl.siml` text (the editor's sim).
- `siml lsp`: the language server on stdin and stdout (LSP 3.17, JSON-RPC with Content-Length).
- `sim --infile x.siml`: sims a full setup, or a preset build over its spec's defaults.siml, with the request built
  as the site builds it, without the potions and conjured items the site adds for its APL.
- `make siml`: writes `names.json` and this skill again, then runs `siml fmt -check ui/specs`. Run it before
  committing and after any change to `proto/apl.proto`.

## Language server

Start `bin/wowsimcli siml lsp` (`make bin/wowsimcli`) with the repository root as its working folder, and
send `.siml` documents (languageId `siml`). It answers completion, hover, definition, references, rename, document
symbols, folding, semantic tokens, formatting, code actions (quick fixes) and document links, and publishes
diagnostics. Names complete from `sim/siml/names.json`, items from the database. In VS Code, `tools/vscode-apl`
(built into `.vscode/extensions/wowsims-apl`) builds and starts the server itself; Zed's `tools/zed-siml` runs
`go run ./sim/siml/lsp/launch`, which builds it and starts it in one command. The initialization option
`"simCommands": true` adds sims as code actions and lenses (`siml.sim`, `siml.compare`) with each row's runs per fight
as inlay hints, for an editor with no panel (`sim/siml/lsp/commands.go`).

## Files

- `x.apl.siml` is a rotation, `x.gear.siml` a gear set (no spec line needed), `x.siml` a full setup with sections.
- The first lines are `siml 1`, then `spec <Player spec oneof field>` (`hunter`, `dps_warrior`,
  `retribution_paladin`, …). An `x.siml` may then have `talents "…"` and `use "path" [with $var = value, …]`, which
  takes another file's sections, variables and defs in; a rotation file of only `var` and `def` lines shares them
  between rotations.
- `// comment` goes anywhere and never reaches the proto. `/// note` above a priority or group row is its notes.
  `# ` before a row hides it (kept with `"hide": true`).
- Indent with 2 spaces; a long row continues on deeper lines.
- Raw JSON in backticks stands for anything with no SIML form: ``cast `{"spellId":31016}` ``.

## Setup sections

An `x.siml` has these sections: `settings:` `consumables:` `buffs:` `party_buffs:` `raid_buffs:` `debuffs:`
`encounter:` `sim:` `gear:` `item_swap:` `apl:` `simple:` `cooldowns:` `prepull:` `priority:` `group "<name>":`.

Entries are `field value` lines or comma lists of flags (`raid_buffs:` `gift_of_the_wild, windfury_totem`);
`sim: iterations 25000` fits one line. Gear rows are `<slot> <item> [<suffix>] [+ <enchant>]`, the slots `head`
`neck` `shoulder` `back` `chest` `wrist` `hands` `waist` `legs` `feet` `finger1` `finger2` `trinket1` `trinket2`
`main_hand` `off_hand` `ranged`.

## Rotations

```
siml 1
spec hunter

var ${Use Multi-Shot} = true          // a sim variable: a value read while the fight runs; $use_multi_shot
def fits(x) = spell(x).cast_time < 2s // a def: text substituted where it is called, parameters replaced
def filler = arcane_shot              // a def that is a name stands for it where a name goes

prepull:
  -2s cast aspect_of_the_hawk         // a prepull row starts with its time

priority:
  cast hunters_mark if not target.aura(hunters_mark).is_active
  cast multi_shot if $use_multi_shot and fits(multi_shot)
  when current_time > 5s:             // joins its condition to every row under it
    cast filler if spell(filler).is_ready
  group "Weave" if self.unit_distance > 5
  cast rapid_fire if current_mana_percent >= 50%

group "Weave":
  move 5
  wait 400ms
```

- **Steps:** `cast x [on unit]`, `channel x [on unit] [until value] [recast]`, `wait v`, `wait until v`, `move v [recheck]`,
  `move for v`, `group "N" [with %p = v]`, `schedule "0s, 60s" <step>`, `sequence "N" [a, b]`, `none`, and any
  action kind below, bare (`autocast_other_cooldowns`) or with arguments (`multidot(rend, max_dots=3)`). `if <value>`
  conditions a row.
- **Values:** `1.5s` `400ms` `1m30s` `30%` `7` `true` `false` `"text"` `none`, `$var` or `${Exact Name}`,
  `%placeholder` (a group's), `and` `or` `not`, `==` `!=` `<` `<=` `>` `>=`, `+` `-` `*` `/`, `max(a, b)`,
  `min(a, b)`, `[unit.]head(x).property[(arg=v)]`, `[unit.]kind`, `kind(…)`, a def call. Precedence, loosest first:
  `or`, `and`, `not`, comparisons, `+ -`, `* /`.
- **Arguments:** positional first, then `field=value`. A bool field written bare sets it, and the printer writes
  `is_active(include_reaction_time=true)`.
- **Units:** `self` `target` `previous_target` `next_target` `all_targets` `all_players` `targetN` `playerN` `petN`
  (N from 1) `none`.

## Names

A name is the game name in snake_case, read in a namespace by its position: spell (`cast`, `spell()`, `dot()`),
aura (`aura()` on self, player or pet), target_aura (`target.aura()`), target_spell (`boss_spell()`), pet_aura,
item, enchant, suffix.

- Spell-like names are the file's class's, else shared (gear, consumables, encounters).
- An item in a spell position is `item.<name>` (`cast item.major_mana_potion`); `other.<name>` is an OtherAction
  (`other.offensive_potion`).
- Ranks and duplicates carry suffixes: `frostbolt_rank10`, `heroic_strike_tag1`, `fireball_18082`.
- A name the table lacks is `unknown-name` with a did-you-mean; `make siml-names` adds newly registered spells.
- `$var` where a name goes (`cast $filler`, `aura($curse)`) is `spell-variable`: ActionID has no member to name a
  variable in. A def for a name (`def filler = arcane_shot`, then `cast filler`) picks the spell in one line.
